# 网站转型：GitHub 具体功能调研

调研日期：2026-10-25（Asia/Shanghai）。

本轮目标：寻找用户能实际使用、能看见明确结果、适合以 Java 后端为主要工程实现的网站功能。允许放弃原有 AI 聊天平台定位。本文是候选功能与选型调研，不代表这些功能已经实现、部署或通过运行验收；本轮只读取开源仓库 README、功能文档、仓库元数据与部分 LICENSE，没有安装、运行这些项目，也没有修改线上服务。

## 选型结论

优先比较以下三个独立方向；先选其中一个形成完整产品，再决定是否组合。

1. **Excel 变在线业务应用**：上传设备台账、客户跟进表或报名表，得到可共享的数据页面、填报表单、权限和统计。产品适用面广，Java 可以承担数据与业务引擎。
2. **网页变持续更新的数据表和 API**：用户在网页里选取字段、演示翻页，保存机器人，定期采集并查看变化。现场演示效果突出，Java 可以直接使用 Playwright 执行浏览器步骤。
3. **出错一键生成可回放的 Bug 链接**：记录报错前的网页操作，并关联接口与 Java 后端链路。研发团队能直接用于沟通和排查问题，后端核心是事件采集、存储、索引与关联。

本轮排序是依据需求做的判断，不是用户增长、商业收入或技术性能的实测排名。

| 功能 | 用户输入 | 得到的实际成果 | Java 承担的核心工作 | 相对开发量 |
| --- | --- | --- | --- | --- |
| Excel 变业务应用 | 一个 Excel/CSV，确认字段和权限 | 在线应用链接、表单、数据视图 | 元数据引擎、查询、权限、版本与导入 | 大 |
| 网页变数据机器人 | URL、字段、翻页步骤、周期 | 自动更新的表格、差异记录、API | 执行调度、浏览器隔离、去重、快照 | 中到大 |
| Bug 回放链接 | 接入采集 SDK，用户报告问题 | 可播放的操作过程与关联接口/Trace | 事件接收、分块存储、索引、鉴权 | 中到大 |
| MySQL 变经营看板 | 只读数据源、业务口径、问题 | 可刷新图表、明细下钻、可检查 SQL | JDBC、查询约束、数据权限、缓存 | 中到大 |
| 批量文档变结构化表格 | 一批文件、所需字段 | 可复核的数据表、原文定位、导出 | 批任务、规则校验、复核与版本 | 中 |
| ER 图变可运行 Java 工程 | 实体、字段、关系、生成选项 | 编译运行的 Spring Boot 项目与下载包 | 模型校验、模板、构建执行、版本 | 大 |

## 候选一：上传 Excel，生成可共享的业务应用

### 具体使用过程

用户上传一份「设备借用.xlsx」，包含设备编号、设备名称、借用人、借出日期、归还状态。网站先展示字段识别结果，用户确认后得到：

- 可筛选、排序、分页的设备列表和详情页。
- 新增/编辑表单，以及一个可分享的借用申请表单链接。
- 管理员与普通成员两类权限，服务端执行数据访问限制。
- 在借、逾期、已归还的统计视图。
- 数据导出与操作记录。

同一引擎后续可以创建客户跟进、社团报名、门店库存等应用。最初只完整做好一个设备台账模板，避免把第一版扩成通用 ERP。

### 本轮确认的开源事实

- [Teable](https://github.com/teableio/teable) 将表格、数据库协作、视图、权限和 API 结合，并展示 AI 应用与工作流方向。
- [Baserow](https://github.com/baserow/baserow) 提供表格式数据库、应用构建、自动化和看板，文档明确采用前后端解耦的 API 设计。

### 在本网站如何实现

借鉴字段配置、视图和表单的产品设计；Java 自己实现应用元数据、字段类型、动态查询、导入和权限。先限制字段类型为文本、数字、日期、枚举和布尔值，避免让模型直接生成并执行任意数据库结构变更。

第一版的数据模型至少包括 `app`、`table_definition`、`field_definition`、`view_definition`、`member_permission`、`import_job` 与记录版本。物理表、JSON 存储或混合存储应做一轮小规模性能与迁移验证后再选，不能只因为实现方便就决定长期结构。

AI 的作用是提出字段类型、校验规则和统计建议，用户确认的结构才进入业务引擎。

### 可以拿出来演示的结果

上传真实表格 → 确认字段 → 产生应用链接 → 第二个账号填写 → 管理员看见新增记录和统计 → 同时编辑时检测版本冲突。

### 复用边界

[Teable LICENSE](https://github.com/teableio/teable/blob/develop/LICENSE) 区分 AGPL 核心应用与 MIT 包，并列有品牌附加条款；不能把整个产品当成可直接换标的组件。[Baserow LICENSE](https://github.com/baserow/baserow/blob/develop/LICENSE) 区分 OSE、premium、enterprise 与文档内容。本候选优先采用设计参考和明确许可的组件，不默认复制商业模块。

## 候选二：圈出网页内容，生成持续更新的数据表和 API

### 具体使用过程

用户打开一个公开招聘列表，在内嵌浏览器中点选职位、公司、地点、薪资和详情链接，再演示一次翻页。保存后，网站定期运行同一流程，展示：

- 当前职位表，支持导出 Excel。
- 新增、删除、字段变化和采集时间。
- 每行数据对应的来源 URL 和页面证据。
- 一条读取最新结果的 API。
- 按确定规则筛选变化，例如「新增 Java 岗位且地点为武汉」后产生站内通知。

商品目录、公告、公开招标等可以成为后续模板。第一版优先公开列表页，不承诺适配所有网站；遇到登录、验证码或页面结构无法识别时给出明确状态。

### 本轮确认的开源事实

- [Maxun](https://github.com/getmaxun/maxun) 支持录制浏览器动作形成可复用提取机器人，也提供 AI 提取、监控和 API 方向。
- [changedetection.io](https://github.com/dgtlmoon/changedetection.io) 支持页面变化比较、元素选择、周期检查与通知。当前 README 将部分 AI 变化摘要能力标注为托管服务能力，因此不能直接把它视为社区版全部可复用。
- [Skyvern](https://github.com/Skyvern-AI/skyvern) 提供 AI 与 Playwright 结合的浏览器操作、结构化提取和工作流 SDK，可作为交互和执行思路参考。
- [Playwright Java](https://playwright.dev/java/docs/intro) 有官方 Java/Maven 接入方式，浏览器执行器可以使用 Java，无需为了浏览器控制而固定采用 Python 后端。

### 在本网站如何实现

第一版采用受限的步骤模型：打开页面、等待元素、提取字段、点击下一页、结束。Java 保存流程版本并调度执行器，控制每个用户的并发和运行时间；以业务字段与来源链接进行去重，保存每次运行快照，按字段计算差异。AI 在选择器失效时提出候选修复或补充提取规则，不能把提取失败伪装为空结果。

### 可以拿出来演示的结果

网页点选字段 → 自动翻两页 → 得到表格 → 修改测试页面中的一条记录 → 再运行时只显示这条记录的变化 → 用 API 读取新结果。

### 复用边界

Maxun 和 Skyvern 的当前仓库元数据显示 AGPL-3.0；changedetection.io 为 Apache-2.0。若选定此方向，要按实际采用的模块与版本决定直接部署、调用独立服务还是参考设计后自行实现。本轮未进行各网站适配、吞吐和采集成本实测。

## 候选三：网站出错时，一键生成可回放的 Bug 链接

### 具体使用过程

接入方在自己的网站中安装采集 SDK。用户遇到「点了按钮没反应」或接口报错，点击「报告问题」，将本次经过确认的记录提交为一个链接。开发者打开后可以：

- 播放用户在网页里的点击、滚动和页面变化。
- 拖动时间线查看错误发生前后的步骤。
- 查看同时发生的接口失败和控制台错误。
- 在接入后端链路采集的情况下，跳转到对应 Java 请求与数据库调用。
- 导出复现步骤，并把解决状态与新版本关联。

### 本轮确认的开源事实

- [rrweb](https://github.com/rrweb-io/rrweb) 提供 DOM 快照、增量事件录制、重建与播放器，可用于网页会话回放，当前许可为 MIT。
- [OpenTelemetry Java Instrumentation](https://github.com/open-telemetry/opentelemetry-java-instrumentation) 提供 Java agent 与库级遥测接入，包含常见框架和 JDBC 相关能力。

### 在本网站如何实现

Java 接收分块事件，按会话序号检查重复与缺口，压缩后保存到对象存储，数据库维护时间范围、项目、版本、错误和 Trace 索引。前端按时间窗口加载回放片段。通过项目、会话 ID 和传播的 Trace 上下文关联浏览器请求与后端链路。

请求和控制台数据需要单独接入采集，不能假设 rrweb 的 DOM 录制已经包含完整网络信息。rrweb 的回放重现页面状态，不等于重新执行原业务请求；自动生成可运行测试应作为后续独立能力验证。

输入遮蔽、项目访问权限、分享链接有效期和录制保留期是此功能的数据模型组成部分，第一版就需要落实。

### 可以拿出来演示的结果

在本站测试版故意触发一个失败 → 点击报告 → 分享链接 → 另一账号回放操作 → 选中错误请求 → 查看同一次后端异常链路。这里使用受控演示缺陷，不把演示结果写成已经发现的线上问题。

## 候选四：连接 MySQL，一句话生成能刷新和下钻的经营看板

### 具体使用过程

商家连接一个只读订单库，确认「实收金额」「退款金额」「有效订单」的口径，输入：「做一个最近 30 天销售看板，能点到商品明细。」网站生成可保存的图表布局，每张图可以检查 SQL、计算口径和数据更新时间，点击后查看明细并导出。

### 本轮确认的开源事实

[WrenAI](https://github.com/Canner/WrenAI) 提供语义层、受约束的自然语言转 SQL 与数据接入思路。当前 README 明确区分开源引擎和商业 GenBI UI、看板、部分权限能力；[LICENSE](https://github.com/Canner/WrenAI/blob/main/LICENSE) 按目录划分许可，核心与 SDK 等目录为 Apache-2.0。

### 在本网站如何实现

Java 完成 JDBC 数据源管理、表字段元数据、业务指标定义、查询执行与取消、超时和结果行数控制、权限与结果缓存。AI 输出结构化的查询和图表候选；SQL AST 校验、数据库只读账号与执行限额共同约束实际查询。业务口径需要用户确认，不能根据字段名称推断后就宣称财务数字正确。

第一版只做 MySQL 与三种图表，支持保存、刷新、筛选和一个可分享看板；不同时建设通用 ETL 和多数据源联邦查询。

### 可以拿出来演示的结果

导入示例订单数据 → 定义有效订单规则 → 生成看板 → 点击图表下钻 → 修改一条符合/不符合规则的测试订单 → 刷新后核对实际聚合结果。

## 候选五：一批 PDF、合同或发票，变成可复核的结构化表格

### 具体使用过程

用户拖入一批采购单，配置要提取供应商、采购单号、日期、明细和金额。网站展示待处理、处理中、待复核和已完成的文件；点击任意单元格可以看到对应文件及来源片段。缺少字段、重复单号、明细与总额不一致的记录进入复核队列，修正后批量导出。

### 本轮确认的开源事实

- [Docling](https://github.com/docling-project/docling) 支持多格式文档解析、PDF 版面、表格、OCR 与结构化表示；代码许可为 MIT，具体模型使用另看模型许可。其结构化字段抽取相关文档标注为 Beta，不能把任意版式的精确抽取当成已有保证。
- [OpenContracts](https://github.com/Open-Source-Legal/OpenContracts) 支持文档标注、来源关联、批量字段提取与逐单元格人工审核；当前主仓库 [LICENSE](https://github.com/Open-Source-Legal/OpenContracts/blob/main/LICENSE) 为 MIT。

### 在本网站如何实现

解析/OCR 可以复用独立服务；Java 实现批任务、文件去重、字段模式、校验规则、复核流程、结果版本、失败重试和导出。每个提取值携带来源位置与处理版本，规则冲突和没有证据的值明确标记为待复核。

第一版只做好一种采购单或发票模板，验证字段、金额与来源定位，再增加版式和文件类型。处理速度、准确率和资源占用需要用自己的样本测量。

## 候选六：画好 ER 图，得到可运行和下载的 Spring Boot 工程

### 具体使用过程

用户画出商品、分类和库存表，设置字段、关系、校验和唯一键。点击生成后得到：

- 数据库迁移、Java 实体、DTO、基础业务与接口代码。
- OpenAPI 文档和基础接口测试。
- 独立临时环境中的编译日志、启动状态与试调页面。
- 可以下载并在本地继续开发的源码包。

### 本轮确认的开源事实

- [drawDB](https://github.com/drawdb-io/drawdb) 提供浏览器 ER 图编辑、SQL 导入导出等能力，当前许可为 AGPL-3.0。
- [JHipster](https://github.com/jhipster/generator-jhipster) 提供应用生成器；其 [JDL 文档](https://www.jhipster.tech/jdl/) 展示如何描述应用、实体与关系，许可为 Apache-2.0。

### 在本网站如何实现

Java 自己维护一套可验证的模型定义，检查字段、主外键、保留字和命名冲突；用版本化模板生成工程，交由隔离构建执行器编译、测试和启动。构建结果、模板版本、错误与产物归档保存，支持重复生成时比较差异。

第一版只承诺基础 CRUD、一对多关系和明确的字段校验。真实库存扣减、付款等业务状态机需要独立设计，不能仅靠表结构自动生成后宣称业务正确。

## 两个展示很强，但不作为 Java 主线首选的补充

### 保留原排版的双语 PDF 翻译

上传英文论文 → 选择术语和页码 → 生成原文/译文对照 PDF。参考 [BabelDOC](https://github.com/funstory-ai/BabelDOC)；其 README 提供 Python API、双语排版与页面处理选项，表格和扫描件等仍有明确实验/适配边界，当前许可为 AGPL-3.0。Java 的工作主要是文件与任务系统，核心排版与翻译流水线来自 Python，因此更适合作为独立工具模块。

### 描述一句话，生成一个可使用的小工具

输入「做一个排班表」 → 生成可编辑、可预览的小应用 → 发布成链接。参考 [bolt.diy](https://github.com/stackblitz-labs/bolt.diy) 和 [Dyad](https://github.com/dyad-sh/dyad)。这两项本轮主要检查仓库定位、元数据与 Dyad 的许可说明，尚未深入验证其构建链。生成侧主体是 TypeScript；Java 可承担会话、执行配额、构建任务和产物管理，但要承担 Java 核心项目，还需自己建设有实际作用的执行与服务能力。

## 用于做决定的建议

- **希望面向更多普通用户并形成完整产品**：先选「Excel 变业务应用」。第一版专注设备台账，把导入、权限、表单、数据修改、统计和导出做完整。
- **最重视现场演示时看得见自动化过程**：先选「网页变数据机器人」。第一版做到公开列表页选字段、翻页、定时运行、字段差异和 API 读取。
- **最重视研发团队直接使用以及 Java 工程贡献**：先选「Bug 回放链接」。第一版把浏览器回放、接口错误和 Java Trace 关联成一次可访问的报告。

上面三项都可以独立替换网站主定位，不需要先建设通用 AI 项目工作台。现有账号、文件、通知和 SSE 可按需要复用；是否保留原有聊天、模型商城、点数和订阅，应在选定方向后按新用户流程决定。

## 实现后的有效证据

不同功能的成果应分别测量：应用的数据权限与并发编辑、机器人任务成功/失败与恢复、Bug 事件丢失/重复与回放定位、查询正确性与延迟、文件字段复核结果、生成工程实际编译与接口通过情况。简历中的规模、时延和效果只使用后续真实测量结果，本文不预填业绩数字。

沿用已有开发约束：每个选定能力先完成隔离本地实现、相关接口/浏览器/故障验证与验收记录，再进入该批次的生产发布流程。候选比较不等于已选定开发范围，也不触发本轮线上部署。
